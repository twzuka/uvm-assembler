# Ассемблер и интерпретатор УВМ, вариант 13

Практическая работа № 3 по дисциплине «Конфигурационное управление».
Источник требований: «ИКБО-40-25 (4).pdf», вариант 13, страницы 56-59;
общие требования к репозиторию: страницы 4-7.

## Состояние: этап 3, интерпретатор и память

Ветка `stage-3-memory` продолжает `stage-2-codegen`.
Реализованы разбор команд, проверка полей и формирование бинарного файла.
На этапе 1 выводились поля A-E, на этапе 2 режим `--test` выводит байты.
Сборка не требуется. Нужен Python 3.10 или новее; внешних зависимостей нет.

```sh
python -B -m src.uvm assemble examples/spec_tests.asm output/spec.bin --test
python -B -m unittest discover -s tests -v
```

Запускать из корня репозитория. В Windows вместо `python` можно использовать
`py -3`, в Linux/macOS - `python3`. Скрипты `run.bat` и `run.sh` принимают
те же аргументы, начиная с `assemble`. Переменная `PYTHON` задаёт путь
к интерпретатору; по умолчанию используются `python` и `python3` соответственно.

## Язык ассемблера

Одна команда на строку: `МНЕМОНИКА B, C[, D, E]`. Регистр мнемоники
не важен. Аргументы разделяются запятыми. Поддерживаются беззнаковые
десятичные числа и шестнадцатеричные с префиксом `0x`. Пустые строки
игнорируются; комментарий начинается с `;`. Меток, макросов и псевдокоманд нет.

| Мнемоника | Поля | Семантика | Размер |
| --- | --- | --- | --- |
| `LOAD_CONST B, C` | A=5, B:26 бит, C:31 бит | `M[C] = B` | 8 байт |
| `READ_MEM B, C` | A=14, B:31 бит, C:31 бит | `M[B] = M[C]` | 9 байт |
| `WRITE_MEM B, C` | A=9, B:31 бит, C:31 бит | `M[B] = M[C]` | 9 байт |
| `EQ B, C, D, E` | A=3, B:13 бит, C/D/E:31 бит | `M[E] = (M[C] == M[M[D] + B])` | 14 байт |

`M[x]` обозначает содержимое ячейки по адресу x. Чтение и запись в методичке
описаны одинаково: сохранены обе команды с разными кодами A.
Код A занимает биты 0-3. Поля идут подряд от младших битов;
неиспользуемые старшие биты команды должны быть нулевыми.

Диапазоны: B константы 0..67108863, B смещения 0..8191,
все адресные поля 0..2147483647. Выход за диапазон считается ошибкой.

## Проверка этапов 1 и 2

Файл `examples/spec_tests.asm` содержит все тесты спецификации.
Ожидаемый вывод с `--test` в ветке этапа 1:

```text
A=5, B=870, C=362
A=14, B=805, C=879
A=9, B=594, C=839
A=3, B=318, C=533, D=743, E=571
```

На этапе 2 тот же исходный файл даёт:

```text
0x65, 0x36, 0x00, 0x80, 0x5A, 0x00, 0x00, 0x00
0x5E, 0x32, 0x00, 0x00, 0x78, 0x1B, 0x00, 0x00, 0x00
0x29, 0x25, 0x00, 0x00, 0x38, 0x1A, 0x00, 0x00, 0x00
0xE3, 0x13, 0x2A, 0x04, 0x00, 0x00, 0xE7, 0x02, 0x00, 0x80, 0x1D, 0x01, 0x00, 0x00
Размер двоичного файла: 40 байт
```

Формат little-endian следует из эталонных байтов методички.
Упаковка: `A | (B << 4) | (C << 30)` для константы;
`A | (B << 4) | (C << 35)` для чтения/записи;
`A | (B << 4) | (C << 17) | (D << 48) | (E << 79)` для сравнения.
Затем число сохраняется в 8, 9 или 14 байтах соответственно.
Заголовка и разделителей между командами нет.

`encode_instruction` кодирует одну команду, `encode_program` соединяет
результаты. `decode_instruction` выполняет обратное преобразование
с проверкой кода, размера и неиспользуемых битов. Проверяются также
максимальные значения полей, случайные значения и повреждённые команды.

Внутреннее представление: список неизменяемых объектов `Instruction`.
Каждый хранит описание команды `CommandSpec` и кортеж операндов.
`parse_source` разбирает текст, `fields` возвращает именованные поля,
`describe` формирует тестовый вывод. Ошибки содержат номер строки;
CLI завершает работу с кодом 1, ошибки аргументов CLI - с кодом 2.

## Структура

- `src/uvm/spec.py` - размеры полей и промежуточное представление.
- `src/uvm/assembler.py` - разбор исходного текста.
- `src/uvm/codec.py` - упаковка и декодирование машинных команд.
- `src/uvm/cli.py` - аргументы командной строки и сообщения.
- `tests/` - автоматические проверки.
- `examples/` - исходные программы, необходимые для защиты.

Бинарные результаты, дампы в `output/`, кэши Python и настройки редакторов
исключены из Git. Каждый следующий этап сохраняется в новой ветке на основе
предыдущего; итог пяти этапов будет в `main`.

## Этап 3. Интерпретатор и общая память

```sh
python -B -m src.uvm assemble examples/copy_array.asm output/copy.bin
python -B -m src.uvm run output/copy.bin output/copy.json --start 1000 --end 1104
```

Интерпретатор получает бинарный файл, путь JSON-дампа и обязательные параметры
`--start`/`--end`. Обе границы включаются в дамп. Например, для ячейки 1002:

```sh
python -B -m src.uvm run output/copy.bin output/cell.json --start 1002 --end 1002
```

```json
{
  "start": 1002,
  "end": 1002,
  "memory": {
    "1002": 116
  }
}
```

Программа копирования занимает 85 ячеек. Исходный массив M[1000..1004]
и копия M[1100..1104] после выполнения равны `[0, 17, 116, 67108863, 42]`.
Промежуточные незаписанные ячейки дампа содержат нули.

### Принятые решения для деталей, не заданных методичкой

- Адрес обозначает одну ячейку с неотрицательным целым числом.
  Число в ячейке не ограничено одним байтом: константа имеет до 26 бит.
- Код и данные находятся в одном хранилище `Memory`. При загрузке каждый
  байт бинарного файла занимает одну ячейку по адресам 0..размер_файла-1.
  Примеры размещают данные после кода, начиная с адреса 1000.
- Хранилище разреженное: отсутствующие ячейки равны нулю; можно обратиться
  к адресу 2147483647 без выделения массива из 2**31 элементов.
- Интерпретатор читает актуальные ячейки общей памяти, а не отдельную копию
  кода. Самомодификация возможна; значение команды вне 0..255 даёт ошибку.
- Счётчик команд начинается с 0, увеличивается на размер текущей команды.
  Завершение - достижение исходного размера бинарного файла. Дополнительной
  команды HALT нет, поскольку её нет в спецификации.
- Неизвестный код, ненулевые резервные биты, обрезанная команда и неверный
  адрес дают ошибку с адресом команды. При ошибке дамп не записывается.

`Machine.step` выполняет чтение, декодирование и исполнение одной команды;
`Machine.run` повторяет цикл до конца программы. `load_constant` и
`copy_memory` реализуют операции памяти. `Memory.read`, `write`, `load`,
`read_bytes`, `dump` предоставляют чтение, запись, загрузку кода, выборку
команд и дамп; `check_address`/`check_range` проверяют адреса.
На этом этапе EQ распознаётся декодером, но ещё не исполняется.
